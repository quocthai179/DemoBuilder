# Demo squad playbook

## Roster

| Agent (`subagent_type`) | Role | Main output |
|---|---|---|
| `demo-builder:demo-director` | Producer: plans, dispatches, gates, checkpoints | Demo plan, final summary |
| `demo-builder:demo-strategist` | Audience, pains, value moments, storyline, CTA | `brief.md` |
| `demo-builder:scriptwriter` | Storyboard + spoken narration, timing | `script.md`, scenes in `demo.yaml` |
| `demo-builder:flow-engineer` | Selectors, actions, login/setup, masks, demo data | `actions:`/`setup:` in `demo.yaml`, green `--dry` |
| `demo-builder:voice-producer` | Provider/voice, lexicon, audio generation | `audio/`, `voice:` block |
| `demo-builder:screen-recorder` | Takes paced to voice, retakes, timing | `recordings/`, `cards/` |
| `demo-builder:video-editor` | Cards, music, captions, exports, thumbnail | `output/` |
| `demo-builder:demo-qa` | Frame-by-frame QA, privacy, claims, pacing | `qa/qa-report.md` |
| `demo-builder:localizer` | Other languages/markets | `.demo/<slug>-<lang>/` |
| `demo-builder:launch-copywriter` | Titles, description, email, social, talking points | `copy/` |

Subagents cannot launch subagents, so orchestration runs from the main session — through the `/demo-builder:*` commands, by following this playbook, or with the director as main agent (`claude --agent demo-builder:demo-director`).

## Pipelines

- **New demo** (`/demo-builder:new`): strategist → scriptwriter → ⏸ user approves brief + script → flow-engineer ∥ voice-producer → screen-recorder → video-editor → demo-qa ⟲ fixes → ⏸ user approves cut → launch-copywriter.
- **Quick fix** (`/demo-builder:retake`): owner of the problem → `tts --scenes` (if narration changed) → `record --scenes` → `assemble` → `review`.
- **Localise** (`/demo-builder:localize`): localizer → voice → (re-record) → assemble → demo-qa.
- **Short/vertical cut**: scriptwriter writes a ≤ 60 s version as a separate spec `.demo/<slug>-short/` (reuse recordings via `paths.recordings` when scenes match) → video-editor with `formats: [vertical]`.
- **Copy only** (`/demo-builder:package`): launch-copywriter.

Individual steps: `/demo-builder:brief`, `script`, `flow`, `voice`, `record`, `edit`, `review`, `doctor`.

## Checkpoints with the user (never skip)

1. Brief + storyboard approved **before** recording (recording is the expensive step).
2. Credentials: which env vars to export; confirm the environment is a demo/staging tenant.
3. Final cut approved before copy, localisation or anything leaves the machine.

## Workspace

```
.demo/<slug>/
├── brief.md            # demo-strategist
├── script.md           # scriptwriter (storyboard table the user approves)
├── demo.yaml           # source of truth: scenes, narration, actions, voice, brand
├── assets/             # logo, music (+ licence), recorded voice files
├── audio/ recordings/ cards/ build/   # generated by the toolkit (git-ignored)
├── review/             # frames, contact sheet, automated report
├── output/             # final deliverables
├── qa/                 # qa-report.md, licenses.md, edit-notes.md
└── copy/               # titles, description, email, social, talking points
```

## Writing briefs for agents

Agents start cold. Every brief contains: goal and audience; slug and paths; upstream artifacts to read; constraints (length, language, tone, brand, must-not-show, deadline); the exact deliverable; and what the toolkit path is (or tell them to resolve it via the `demo-toolkit` skill).

## Handoff format

```
### Handoff
- Status: done | blocked | needs-input
- Artifacts: <paths>
- Next: <agent or user> — <what>
- Risks / open questions: <…>
```

## Quality bar for "done"

`status` all green · no silent draft voice · QA verdict SHIP · length within ±15 % of target · every value moment from the brief visible and emphasised when narrated · no personal/customer data on screen · captions and chapters present · user approved.
